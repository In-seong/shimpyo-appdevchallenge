===[app_summary]===
급속 충전이 시작되는 순간 차량이 스스로 열려, 주행 이력·시각·동승자·차량 상태를 읽고 남은 충전 시간에 딱 맞는 휴식 방법을 먼저 제안하는 앱입니다.

===[planning_background]===
[주목한 순간]
급속 충전은 빨라졌지만 15~30분의 "비는 시간"은 사라지지 않습니다. 고속도로 휴게소에서 충전을 걸어놓은 운전자는 갈 곳이 마땅치 않아 대부분 차 안에 머뭅니다. 명절과 휴가철에는 이 경험이 한꺼번에 몰립니다.

[왜 지금 해결해야 하는가]
· 휴게소 전기차 충전 건수는 추석 전후 5일 기준 2023년 12,503건 → 2024년 25,943건 → 2025년 52,588건으로 2년 만에 321% 늘었습니다. 같은 기간 주유는 7% 줄었습니다. (국회 황희 의원실이 받은 한국도로공사 자료)
· 2026년 8월 기준 도로공사 휴게시설 충전기 1,844기 중 1,229기(67%)가 200kW 이상 고출력입니다. 충전기가 빨라져도 20분 안팎의 대기는 남습니다.
· 전기차 운전자가 가장 불편하게 꼽는 충전 장소는 급속(87%)이며 완속(13%)과 차이가 큽니다.

[기존 서비스와의 공백]
테슬라는 Theater·Arcade로, BMW는 AirConsole로 충전 중 볼거리를 제공합니다. 다만 모두 "메뉴를 띄워 주는" 수준이고, 차가 상황을 읽어 먼저 제안하지는 않습니다. 시트·조명·공조를 묶어 제어하며 완충 직전에 깨워 주는 휴식 경험이나 차량 점검을 붙인 사례도 없습니다. Pleos 앱 마켓에도 충전 대기 시간을 다루는 앱은 아직 없습니다.

[쉼표의 답]
"무엇을 보여줄까"가 아니라 "지금 이 사람에게 무엇이 필요한가"에서 출발합니다. 차량 데이터로 상황을 읽어 네 가지 모드 중 하나를 먼저 제안하고, 모든 기능이 "남은 충전 시간"을 공통 타이머로 삼아 충전 완료에 자연스럽게 맞춰 끝납니다.

===[vehicle_scenario]===
[상황 인식 추천 엔진 — 핵심 차별점]
충전 케이블 연결을 감지하면 여섯 가지 신호를 한 번에 읽어 모드별 점수를 합산하고, 1위 모드를 추천 카드로 먼저 띄웁니다. 추천 이유도 한 줄로 함께 보여줍니다.

신호와 규칙(예시)
· 연속 주행 시간 (Odometer) — 2시간 이상이면 휴식 +3, 1시간 미만이면 콘텐츠·놀이 +2
· 현재 시각 — 22~06시 휴식 +2, 주간 콘텐츠 +1
· 좌석 착좌 (Seat) — 뒷좌석 동승자 있으면 놀이 +3, 혼자면 놀이 -2
· 차량 경고등 (Safety) — 1개 이상이면 점검 +4 (최우선)
· 도착 시 예상 배터리 (NaviHelper) — 20% 미만이면 점검 +3
· 예상 충전 시간 (ChargingPlan) — 15분 이하 콘텐츠 +1, 30분 이상 휴식 +1

동점이면 안전 우선 순서(점검 → 휴식 → 콘텐츠 → 놀이)로 가릅니다. 차량 상태가 운전자 상태보다, 운전자 상태가 즐길 거리보다 앞섭니다. 경고가 있으면 점수와 무관하게 점검이 추천됩니다.

[네 가지 모드와 차량 특화 요소]
· 콘텐츠 — 남은 충전 시간에 길이를 맞춘 재생목록을 만듭니다. 충전 타이머와 내비 경로를 동시에 읽어야 길이를 맞출 수 있습니다.
· 휴식 — 시트를 젖히고 실내 조명을 낮추고 공조를 조절한 뒤, 완충 1분 전에 화면을 서서히 밝혀 깨웁니다. 차량 제어 자체가 기능이라 휴대폰으로는 불가능합니다.
· 점검 — 타이어 경고, 워셔액, 오일·브레이크액 레벨을 한 화면에 보여주고 목적지 도착 시 배터리가 충분한지 미리 판단합니다. 차량 진단 데이터는 차에서만 접근할 수 있습니다.
· 놀이 — 오늘 주행한 거리·평균 속도·탑승 인원을 문제로 바꿔 동승자와 퀴즈를 합니다. 주행 데이터가 있어야 성립하므로 폰 게임이 흉내 낼 수 없습니다.

[피드백 기반 개인화]
출발 직후 한 번만 "아까 휴식 모드, 도움이 됐나요?"라고 묻고, 답을 (시간대 × 동승자 × 주행시간) 조합별 가중치에 ±1씩 누적합니다. 다섯 번쯤 쓰면 "이 운전자는 낮엔 콘텐츠, 밤엔 휴식, 가족 탈 땐 놀이" 같은 패턴이 자리 잡습니다. 차량 로컬 또는 Pleos 계정에 저장하며 외부 서버 전송 없이 동작합니다.

[모바일로는 안 되는 이유 요약]
시트·조명·공조 제어, 차량 진단 데이터, 경로상 충전 계획(ChargingPlan), 좌석 착좌 감지는 모두 차량 앱만 접근할 수 있습니다. 또한 충전 중 운전자가 가장 오래 응시하는 화면은 휴대폰이 아니라 센터 디스플레이입니다.

===[key_features]===
[대상 사용자]
고속도로 휴게소나 여행지에서 급속 충전을 하는 장거리 전기차 운전자입니다. 집 완속 충전은 꽂아두고 자리를 떠나므로 대상에서 제외했습니다.

[대표 시나리오 — 명절 귀성]
오후 2시, 가족 네 명이 2시간 20분을 달려 안성휴게소에 들어옵니다. 배터리 42%, 목표 80%.
1) 충전 케이블을 꽂자 쉼표가 자동으로 열립니다. 상단에 "13분 남음 · 42% → 80%"가 뜹니다.
2) 화면 중앙에 추천 이유가 나옵니다. "2시간 넘게 달리셨어요. 13분 동안 쉬어가는 건 어때요?" 추천 카드는 휴식입니다.
3) 시작하기를 누르면 화면이 어두워지고 중앙에 원형 타이머가 돕니다. 시트가 38도로 젖혀지고 조명이 10%로 낮아지며 공조가 23도로 맞춰집니다.
4) 완충 1분 전, 화면이 서서히 밝아지며 "곧 충전이 끝나요"와 출발 준비 버튼이 나타납니다.
5) 출발 직후 하단에서 작은 카드가 올라옵니다. "아까 휴식 모드, 도움이 됐나요?" 좋았어요를 누르면 야간·가족 동승·장거리 조합의 휴식 가중치가 +1 누적됩니다.

[그 밖의 상황]
· 주말 여행 (40분 주행, 아이들 뒷좌석, 11시) → 놀이 추천. 오늘 달린 거리로 만든 퀴즈를 뒷좌석과 함께 풉니다.
· 출장 이동 (40분 주행, 혼자, 내비 목적지 없음) → 콘텐츠 추천. 목적지가 없어 ChargingPlan이 내려오지 않으므로 배터리 변화율로 추정한 시간이 쓰이고 상단에 "추정" 표시가 붙습니다.
· 심야 주행 (3시간, 혼자, 새벽 2시) → 휴식 추천. "늦은 시간이네요. 눈 붙이고 가시겠어요?"
· 차량 경고 발생 → 놀이 점수가 더 높아도 점검이 최우선으로 추천됩니다. 타이어·워셔액 상태와 도착 시 예상 배터리를 함께 보여줍니다.

[화면 구성]
차량 센터 디스플레이 1920×720 기준, 터치 영역 최소 80×80px, 글자 최소 24px, 한 화면에 핵심 동작 하나. 추천 → 모드 선택 → 네 모드 화면 → 피드백까지 일곱 화면으로 구성했고 전부 구현해 두었습니다.

===[pleos_plan]===
[개발 환경]
Pleos Connect SDK 기반 차량 내 앱으로 개발합니다. Android API 28 이상, Gradle 8.0 이상, Java/Kotlin 요구사항을 따릅니다. 서버 REST인 Vehicle Data API가 아니라 차량 제어가 가능한 Connect SDK를 사용합니다.

[사용 SDK와 실제 메서드]
· Vehicle SDK — EvBattery.getEvChargeSwitchState() 충전 여부, getEvBatteryStateOfCharge() 배터리 잔량, registerEvBatteryStateOfCharge() 실시간 구독 (권한 CAR_ENERGY)
· Vehicle SDK — Seat.getCurrentSeatOccupancy() 착좌, getCurrentSeatBeltBuckledState() 안전벨트, moveSeatBackrestAngle() 등받이 제어
· Vehicle SDK — Light.setAmbientLightBrightness() / setCabinLightSwitch() 실내 조명 제어
· Vehicle SDK — HVAC.setHvacTemperature() / setHvacFanSpeed() 공조 제어
· Vehicle SDK — Safety.getTelltalesInfo() 경고등, hasLowWasherFluidWarning(), getEngineOilLevelState() (권한 CAR_SAFETY)
· Vehicle SDK — Odometer.getTripCurrentDrivingTime() / getTripCurrentDrivingDistance()
· NaviHelper SDK — ChargingPlan(duration, startSoc, endSoc), DrivingState.maxChargingPower, RouteStateInfo.estimatedSocAtDest, getDestinationInfo()
· SpeechToText / TextToSpeech SDK — 출발 직후 피드백 음성 응답

[사전 검증에서 확인한 제약과 대응]
공식 문서를 직접 확인해 아래 세 가지는 제공되지 않음을 확인했고 설계를 고쳤습니다.
· 타이어 실측 공기압 — Tire.getLowTirePressure() 는 저압 경고 임계값(kPa)이며 실측값이 아닙니다. 수치 대신 경고 점등 여부로 상태등을 표시하도록 바꿨습니다.
· 급가속·급제동 누적 횟수 — Brake 는 현재 페달 상태만 제공합니다. 해당 신호를 추천 엔진에서 제외했습니다.
· 다음 정비 예정일 — 해당 API가 없어 오일·브레이크액 레벨로 대체했습니다.

[충전 타이머의 이중 구조]
1순위는 NaviHelper 의 ChargingPlan.duration(초)입니다. 다만 ChargingPlan 은 경로 안내 중일 때만 내려오므로, 목적지를 설정하지 않은 경우를 위해 배터리 잔량 변화율로 남은 시간을 추정하는 폴백을 함께 구현했습니다. 80% 이후 충전 감속을 보정 계수로 반영했으며, 200kW 충전기로 10→80% 가 22분으로 계산되어 한국도로공사 실측치와 일치합니다.

[교체 가능한 구조]
차량 데이터는 PleosVehicleGateway 한 클래스로만 들어오고, 메서드 이름을 실제 SDK와 1:1로 맞춰 두었습니다. 추천 엔진·재생목록·퀴즈·관리자는 이 데이터가 어디서 왔는지 알지 못합니다. API 사용 승인을 받으면 이 클래스의 내부 구현만 실제 SDK 호출로 바꾸면 되고 나머지 로직은 수정하지 않습니다.

[이미 구현한 범위]
추천 엔진, 동점 처리, 최우선 규칙, 피드백 개인화, 충전 타이머와 폴백, 재생목록 생성, 퀴즈 생성, 화면 일곱 장, 운영 관리자(규칙 편집·세션 추적·통계)를 모두 구현해 배포했습니다. 차량 데이터만 시뮬레이터가 공급하며, 심사 중 직접 값을 바꿔 추천이 다시 계산되는 것을 확인하실 수 있습니다.

[2차 PT 심사까지의 계획]
Pleos Connect 에뮬레이터 환경에서 게이트웨이 구현을 실제 SDK 호출로 교체하고, 현재 웹 기반 화면을 Android Automotive 네이티브 화면으로 이식합니다. 화면 명세와 추천 엔진 로직은 이미 확정돼 있어 연동 작업에 집중할 수 있습니다.

===[reference_files]===
[타깃 고객과 모수]
쉼표의 대상은 전기차 운전자 전체가 아니라 그중 이동 중 급속 충전을 하는 사람입니다.
· 국내 전기차 등록 1,160,968대 (2026년 8월, 전체 차량의 4.4%, 국토교통부)
· 현대자동차그룹 비중 약 61% → 약 71만대 (카이즈유 2026년 1분기 신차 등록 누적)
· 실질 모수는 Pleos Connect 탑재 전기차입니다. 국내 최초 적용은 2026년 5월 그랜저 부분변경이고 전기차는 아이오닉 3부터이므로 초기 모수는 신차 중심으로 형성됩니다.

초기 모수가 작다는 점을 숨기지 않겠습니다. 이는 쉼표만의 제약이 아니라 Pleos 앱 마켓에 입점하는 모든 앱이 공유하는 조건이며, 바꿔 말하면 지금이 선점 시점이라는 뜻이기도 합니다.

[사용량을 결정하는 것은 "앱을 찾는 사람"이 아니라 "충전하는 순간"]
쉼표는 사용자가 앱을 기억해 찾아 들어오는 구조가 아니라 충전 케이블 연결에서 자동으로 열립니다. 그래서 분모가 "이 앱을 아는 사람"이 아니라 "급속 충전을 하는 횟수"가 됩니다. 그 횟수는 추석 기준 2년 만에 321% 늘었습니다.

[예상 MAU]
MAU = N × r × a
· N : Pleos Connect 탑재 전기차 누적 대수
· r : 그중 월 1회 이상 이동 중 급속 충전을 하는 비율
· a : 충전 시 실행되는 비율. 자동 실행이므로 0.9로 가정

r 은 공개 통계가 없어 보수 30% / 기준 40% / 적극 60%로 구간을 둡니다. a=0.9 적용 시
· 탑재 1만대 → 2,700 / 3,600 / 5,400
· 탑재 5만대 → 13,500 / 18,000 / 27,000
· 탑재 20만대 → 54,000 / 72,000 / 108,000
· 탑재 50만대 → 135,000 / 180,000 / 270,000

연도를 못 박지 않은 이유는 탑재 차량 보급 속도가 현대자동차그룹의 출시 계획에 달려 있어 외부에서 추정할 값이 아니기 때문입니다. 대신 대수가 정해지면 MAU 가 선형으로 따라온다는 점을 보입니다. r 은 추정이 아니라 측정해야 할 값이며, 운영 관리자가 세션 수와 재방문을 실제로 집계하도록 만들어 둔 것은 출시 후 이 값을 바로 확인하기 위해서입니다.

[Retention — 구조적으로 유리한 지점]
· 재실행 트리거가 사용자 의지 밖에 있습니다. 충전할 때마다 열리므로 이탈하려면 앱을 끄겠다고 적극적으로 결정해야 합니다.
· 쓸수록 정확해집니다. 피드백이 상황 조합별 가중치에 누적되어 사용 이력 자체가 전환 비용이 됩니다.
· 대체재가 휴대폰에 없습니다. 시트·조명·공조 제어와 차량 진단은 차량 앱만 할 수 있습니다.

측정 지표는 실행률(급속 충전 세션 중 쉼표가 열린 비율), 추천 수락률(추천한 모드를 그대로 고른 비율), 피드백 긍정률 세 가지로 정의하고 관리자에 모두 구현했습니다.

[서비스 확대 계획]
1단계 — 고속도로 휴게소 급속 충전 대기 (현재 범위)
2단계 — 휴게소 제휴. 충전 완료 시각에 맞춘 음식 선주문·픽업
3단계 — 충전 외 대기 상황으로 확장. 주차 대기, 세차, 정비 대기. "남은 시간"이라는 트리거 구조를 그대로 재사용합니다
4단계 — 상황 인식 추천 엔진을 다른 Pleos 앱의 공통 레이어로 개방

수익 모델은 2단계부터 성립합니다. 휴게소·정비소 제휴 수수료, 콘텐츠 제휴, 앱 마켓 내 부가 기능이 후보입니다. 1단계는 사용자 확보와 r 측정에 집중합니다.

[현대자동차그룹 관점의 기대 효과]
· 충전 중은 운전자가 차 안에서 화면을 가장 오래, 가장 집중해서 보는 시간입니다. Pleos 앱 마켓 입장에서 가장 가치 있는 사용 시간대이며 쉼표는 그 시간의 첫 진입점이 됩니다.
· 점검 모드는 정비 알림을 자연스럽게 노출해 정비 예약으로 이어지는 접점을 만듭니다.
· 휴식 모드는 시트·조명·공조 제어처럼 현대자동차그룹 하드웨어가 아니면 못 하는 경험을 보여줘, 소프트웨어 중심 차량 전환의 장점을 사용자가 체감하게 합니다.
· 피드백 데이터는 "어떤 상황에서 운전자가 무엇을 원하는지"에 대한 차량 내 경험 데이터로, 향후 다른 Pleos 앱의 추천 기반이 될 수 있습니다.
· 구현 난도가 낮습니다. 추천 엔진 본체가 200줄 미만이고 머신러닝이 없어 입점 후에도 운영 부담이 작습니다.
